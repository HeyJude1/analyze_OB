# 知识图谱与生成方法

## 输入与抽取

同一个算子维护两类输入。一类是 OpenBLAS 专家源码及必要的配对工件，用于抽取知识。另一类是带统一接口的独立通用 C、优化示例、参考和驱动，用于编译、测试和比较。算子同名时，仍须核对数据布局、转置、打包 ABI、数据类型、数据依赖与调用层次。

| 步骤 | 记录与验收 |
| --- | --- |
| 注册工件 | 仓库、版本、路径、行号、哈希、架构、角色、拆分 |
| 抽取源码事实 | 循环结构、控制条件、向量 intrinsic 或汇编指令、可见参数、明确的打包与尾部路径 |
| 配对与分析 | 可比 C 源做结构差分。汇编登记可定位的观察。产品级实现包含多条变换时，记录联合观察 |
| 策略归一 | 将同义动作归为策略概念，作用位置、数据契约、架构或模板不兼容时保留不同变体 |
| 标注来源和证据 | 源码观察、适用假设、已通过测试、真机测量使用不同状态。单次整体性能只能关联到该实现或计划 |

优先收录向量化、展开、多累加器与归约、寄存器分块、缓存分块、循环重排、打包和布局、步长分派与尾部处理。预取、流水与参数特化随来源、适用范围和测量成本补充。对重点策略先记录作用在哪个阶段，然后填写硬条件和能被检验的收益假设。

## 图谱表达

| 对象 | 例子 |
| --- | --- |
| 算子与模式 | DDOT 的逐元素乘积、局部累加和最终归约 |
| 策略概念与实例 | 向量归约概念，AVX2 或 RVV 具体实例 |
| 语义与硬件条件 | 单位步长、允许重排浮点求和、目标支持 FP64 向量和相应工具链 |
| 参数与模板 | 累加器个数、展开因子、RVV LMUL、动态 `vl` 和尾部实现 |
| 策略关系 | 生成的布局必须满足微内核契约。两种尾部实现可能竞争同一位置，也可以在不同分支共存 |
| 执行证据与源工件 | 策略观察锚定文件和行号。计时绑定任务形状、目标机器、编译器、代码版本和对照 |

对于语义和 ISA 条件，查询使用已确认、已否定、未知三种状态。未知硬条件要么要求补全事实，要么在能合法运行时提供运行时分派和已验证回退。性能偏好单独打分。平台规格可用于检查能力，性能排名需要匹配目标环境的测量证据。QEMU 保留为兼容和正确性验证环境。

## 从检索到计划

1. 同时读任务契约和实际硬件画像，识别可迁移的计算模式。跨算子检索按模式寻找参照，并在目标任务上重新检查条件。
2. 将硬条件可判定的实例保留为候选。硬件过滤考虑 ISA 版本、元素类型和工具链。将源平台的数值配置保留为出处，目标配置按参数规则重新实例化。
3. 先筛除非法配置，再对有限候选计划排序。计划保存使用的策略、作用区域、参数与依赖顺序，以及被剔除的原因。寄存器估算针对同一热循环的并发生命期，实际溢出和性能交给编译与测量。
4. 生成器接收任务、原始代码和策略计划。编译和独立数值检查通过后才计时。记录失败类型、修复回合、查询条件和原始结果。

DDOT 的“向量化 + 多累加器 + 向量归约”是一套可对照的计划。AVX2 可用固定宽度和显式尾部，RVV 按硬件与剩余元素计算实际 `vl`，候选 LMUL 会改变寄存器占用。验证时使用不能整除向量长度的输入，并测试不同输入规模与数值分布。DGEMM 则展示另一条依赖链，布局打包先定义，再由与布局匹配的微内核计算，边界及 alpha/beta 语义由接口契约校验。

## 知识质量验收

人工审核按算子、架构、抽取通道、策略类别分层。记录动作、条件、参数范围、来源和关系判定。两位评审先各自标注一部分共同样本，保留分歧并说明裁决标准。报告各字段准确率、抽取查全率、错误归并率、重要策略可达性和人工投入。检索结果另用事先标注的任务判断适用性。日志证据只证明它明确覆盖的任务、候选与环境。

## 已实现的范围

首版隔离图包含 178 个节点、628 条边、49 个策略、49 个模板以及 17 份冻结来源文件。检查了 72 个独立留出来源的哈希与构图源码互斥。DSYMM 共享的两份 C/RVV 文件和一个 AVX2 配置条目写入近迁移审计。历史全量图谱可用于浏览与重放，正式配对使用论文快照。

代码已经支持显式查询条件、过滤冲突、根据画像计算候选参数、按已登记关系排序，以及记录可回放轨迹。Conv1D 暂用人工指定的 DOT 类比入口，只召回抽象策略，参数候选需之后执行验证。跨算子模式自动识别、整套计划的资源分配、条件与归并的人评，以及反例写回仍需实验实现与评估。
