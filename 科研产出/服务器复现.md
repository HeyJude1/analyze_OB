## 离线预检

使用 Python 3.10 或更新版本、支持 AVX2/FMA 的 x86-64 主机和 GCC。RISC-V 功能测试另需支持 RVV 1.0 FP64 intrinsic 的交叉 GCC（原实验使用 14.3）和支持 RVV 1.0 的 `qemu-riscv64`。交叉编译器可通过 `--rvv-cc` 接收 Linux 可执行文件路径。以下回放读取提示中的通用 C，并运行两个目标的编译和正确性检查。

```bash
PYTHONPATH=kg_agent/src python3 -m kgagent.cli validate --data-dir kg_agent/data_thesis
python3 算子输入/verify.py --target x86 --variant arch \
  --report experiments/thesis/.build/x86-arch.json

rvv_cc=/path/to/riscv64-linux-gnu-gcc
snapshot=experiments/thesis/functional_2026-11-19
python3 experiments/thesis/run_functional.py \
  --prepared "$snapshot/prepared" --engine replay --task dgemm \
  --rvv-cc "$rvv_cc" --out "experiments/thesis/.build/server-smoke-$(date +%Y%m%d-%H%M%S)"
```

## 新的模型对照

先按原运行清单设置同一 Ollama 模型与预算。以下命令假定服务器上已启动 Ollama，使用默认 HTTP 端口 `11434`。拉取模型后核对新运行 `run.json` 中的 `model_digest` 与历史 [运行清单](experiments/thesis/functional_2026-11-19/ollama/run.json) 一致。可先加 `--task dgemm` 缩小首次模型调用范围。

```bash
ollama pull qwen2.5-coder:7b-instruct-q4_K_M
run_dir="experiments/thesis/runs/$(date +%Y%m%d-%H%M%S)"
python3 experiments/thesis/prepare_comparison.py \
  --out "$run_dir/prepared" --repetitions 3 --top-k 4 --knowledge-byte-cap 12000
python3 experiments/thesis/run_functional.py \
  --prepared "$run_dir/prepared" --out "$run_dir/ollama" --port 11434 \
  --rvv-cc "$rvv_cc" --model qwen2.5-coder:7b-instruct-q4_K_M
python3 experiments/thesis/summarize_functional.py \
  --prepared "$run_dir/prepared" --run "$run_dir/ollama" \
  --out "$run_dir/结果汇总.md" --json "$run_dir/结果汇总.json"
```

主实验入口直接使用仓库内的 `kg_agent/data_thesis/`。从专家源码重跑图谱抽取时，还需 [建图说明](kg_agent/README.md#论文实验快照) 中的原始输入目录。旧实验日志记录了当时的本机绝对路径，复现时使用以上命令填写本机工具链。QEMU 输出用于验证功能。x86 和 RISC-V 的真机计时流程见 [成对计时](experiments/thesis/README.md#成对计时)。
