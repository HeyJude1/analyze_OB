# 九算子四组功能对照

目标是在同一模型和预算下观察生成代码能否编译、能否通过公开数值与接口检查，以及一轮修复解决了哪些问题。测量范围是本机 Windows x86 与 RISC-V QEMU。两端都执行正确性检查。

## 本轮结果

72 个单元均完成，共调用模型 125 次。整体编译通过从 **35/72（48.6%）** 升至 **44/72（61.1%）**，正确从 **18/72（25.0%）** 升至 **19/72（26.4%）**。53 次修复中有 **1 次**转为正确，24 次的候选代码哈希与首轮完全相同。

| 方法 | x86 编译 | x86 正确 | QEMU 编译 | QEMU 正确 |
| --- | --- | --- | --- | --- |
| 无外部知识 | 7 → 7 | 4 → 4 | 5 → 5 | 3 → 3 |
| 文本 RAG | 4 → 3 | 1 → 1 | 5 → 6 | 1 → 2 |
| 独立策略卡 | 3 → 6 | 3 → 3 | 2 → 6 | 2 → 2 |
| 约束规划 | 4 → 6 | 3 → 3 | 5 → 5 | 1 → 1 |

每格为首轮到允许一次修复后的通过数，分母均为 9。单次全矩阵里，约束规划在两个目标上的正确数均未超过独立策略卡或无外部知识组。编译率的变化不能替代功能指标。最终按划分统计，建图内 13/32、独立 BLAS 留出 3/24、DSYMM 近迁移 0/8、Conv1D 外部留出 3/8。

首轮有 36 个编译错误和 1 个编译超时，其中 11 个编译错误归为 intrinsic 或目标不匹配，4 个为缺少头文件。首轮编译通过但未完成正确验证的单元包括 15 个数值或内存契约失败、1 个运行超时及 1 个异常退出。修复后数值或内存契约失败增至 18 个，与部分候选从编译失败转为可执行但结果错误相符。[分类明细](结果汇总.md) · [逐例诊断](失败案例.md)

125 次调用均有 token 记录。观察到最大输出 1,067 token，最大输入输出总量 4,215 token，均在共同预算内。首轮单一次重复用于定位问题。后续重复应保留当前协议与结果，再独立检验更严格的目标 ISA、运行前分支检查及修复策略。

## 无外部知识与约束规划的配对复核

合并两端后，无外部知识组首轮编译通过 **12/18**、功能正确 **7/18**，约束规划组首轮编译通过 **9/18**、功能正确 **4/18**。一轮通用修复后，约束规划的编译通过升至 **11/18**，两组正确数维持原值。同一算子与目标共有 18 对，两组都通过 3 对，都失败 10 对。仅无外部知识通过的有 4 对，分别为两端 DAXPY、RISC-V Conv1D 和 x86 DSYMV。仅约束规划通过的是 x86 DGEMV，独立策略卡也通过了该单元。

四组首轮都收到通用 C 实现、接口契约和目标画像。无外部知识组的 7 个正确候选中，两端 DDOT 和 Conv1D 共 4 个候选去掉首尾空白后与输入 C 完全相同。这一对照衡量的是从通用 C 出发的目标代码改写，经过 `-O3` 编译的候选以数值与接口正确性验收。优化收益需要在保留这些正确候选的前提下与输入 C `-O3` 做性能对照。

约束规划组与独立策略卡组的 18 对提示使用相同的卡片 ID 和顺序。规划组额外加入目标参数和规划字段，18 个规划中有 6 个的关系列表为空。这轮比较估计的是这些字段一起加入后在当前提示实现中的差异。当前规划主要约束发给模型的候选策略，代码仍由模型自由生成。例如 RISC-V DAXPY 的步长模板只写了输入 `incx` 的分支，生成候选也仅检查 `incx` 就进入连续写入 `y` 的快路径，功能验证判定其违反 `incy` 契约。RISC-V DGEMV 的规划候选在 `beta=0` 时仍读取旧 `y`，触发覆盖语义的测试。[逐例诊断](失败案例.md)

后续消融可固定相同的卡片和目标参数，单独切换规划关系，再测将条件绑定到目标函数实际变量并加以验证的增量。双步长、零系数、展开尾部和目标指令集可分别统计。当前结果保留为单次重复的对照。

## 冻结设置

- 九个算子、两个目标、四种方法，每单元首轮生成一次。72 个单元包含 32 个建图内、24 个独立 BLAS 留出、8 个 DSYMM 近迁移及 8 个 Conv1D 外部留出。
- 使用本机 Ollama 的 Qwen2.5-Coder 7B Instruct Q4_K_M。模型 digest、温度、seed、编译工具路径和 QEMU CPU 参数记录在 [运行清单](ollama/run.json)。
- 四组统一 8,192 上下文、每轮最多生成 1,536 token，知识组统一最多四张卡和 12,000 UTF-8 字节上下文。字节上限用于本地选卡，实际输入输出 token 以服务返回为准。每个配对共享任务、ABI、硬件画像和基础提示。
- 编译错误、无效输出、运行失败或数值检查失败可触发一次修复。修复输入统一为原任务、失败候选与有长度上限的诊断。数值失败反馈只给失败断言计数和契约检查提示。本次开始时，诊断文本把这个数字写成了失败用例数，所有方法共同使用该文本。汇总以任务单元是否通过为准，执行器已修正后续运行的措辞。
- 评测器的每次编译或执行各有 20 秒上限。早期一条 x86 DAXPY 文本组编译超时由原日志补标，原分类一并保留。测试输出与生成输入独立存放。首轮及修复后均运行同一公开检查集，所得正确率是开发阶段功能结果。

## 任务切分

| 任务 | 用途 | 知识召回 |
| --- | --- | --- |
| DAXPY、DDOT、DGEMV、DGEMM | 建图内对照 | 对应算子 |
| DSCAL、DASUM、DSYMV | 独立 BLAS 留出 | 分别指定 AXPY、DOT、GEMV 的抽象策略 |
| DSYMM | 近迁移 | GEMM 抽象策略。两者在已有 OpenBLAS 语料中共享源码 |
| Conv1D | 外部留出 | DOT 抽象策略 |

留出任务的类比来源由任务设计固定，作为输入配置记录。模型收到通用 C、契约、预算内知识与目标画像。测试和优化参照在评估端。

复核了 72 份提示的哈希、18 个任务与目标配对、每个配对的基础提示一致性，以及知识组四张卡与字节上限。留出组选择的策略 ID 均属于图谱抽象层。DSYMM 与 GEMM 共享专家源码，因此结果单列。

## 复现

在 `科研产出` 下启动已有的本地 Ollama 服务并加载运行清单中的同一模型。使用原始输入目录和不同的输出目录可重跑。

```powershell
$run = "experiments/thesis/functional_2026-11-19"
python experiments/thesis/run_functional.py --prepared "$run/prepared" --out "$run/reproduction" --rvv-cc "<WSL 内 GCC 14.3 可执行文件路径>"
python experiments/thesis/summarize_functional.py --prepared "$run/prepared" --run "$run/reproduction" --out "$run/reproduction-summary.md"
```

输出目录已有运行清单时，执行器检查固定参数后跳过已完成单元。原实验的 RISC-V 检查在 WSL 中调用静态交叉编译器和 QEMU。执行器也支持 Linux 直接调用这两种工具。Ollama API 留存每轮可用的输入和输出 token。[Linux 复现指南](../../../服务器复现.md)
