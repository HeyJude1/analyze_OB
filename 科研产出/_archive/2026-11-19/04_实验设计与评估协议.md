## 0. 一句话结论

**"这个方向没有 baseline"是误判，而且用户的资产条件很好**：用户已有 `C:\Users\MSI\Desktop\cx_operator_tool\`（45 个 OpenBLAS 算子 × 通用 C/RVV/CX 实现 + 现成的逐尺寸正确性与加速比 harness + RISC-V/CX 工具链），还已有 Morph 的 pilot 性能数据（`07` 复算：硬件信息注入 1.73×，但直接注入策略掉到 0.50×——这恰好是"需要带适用条件的结构化知识"的经验动机）。因此协议定为：**定位按 01 推荐的 C（跨架构策略迁移：实证+协议）**，主任务 **T1「硬件条件化/跨架构的算子优化代码生成」**，数据自建 **OpOptBench-45**；性能只在**原生 x86-64** 上测（严格区分单线程/四线程口径），RVV/CX 只在 QEMU 上验**正确性与结构泛化**；baseline 分三层（编译器 Floor / OpenBLAS 与 Ansor 参照 / 同 LLM 同内容量的方法学 baseline），并用 **2×2 因子设计（知识组织方式 × 内容丰度）+ 三组结构消融**把"图结构的增量"与"知识内容的增量"分开。全部实验**按 2027-01 底小论文投稿倒排**，12 周出主结果，成本量级为**几十到几百元** LLM 费用。

## 2. 为什么"没有 baseline"是误判（给用户和审稿人的五条证据链）

1. **任务有天然的四层参照**：输入就是 `*_k.c`（通用 C 朴素实现）→ Floor=1.0×；同一份输入用 `gcc -O3 -march=<profile>` 重编译就是**编译器基线**（最容易被追问"是不是只赢在 O3"）；系统 OpenBLAS 是**专家上界**；TVM Ansor 是**自动调优上界**（等时预算）。
2. **方法学 baseline 可以严格构造**：同 LLM、同 token 预算、同尝试次数下，B0 零样本 / B1 +硬件信息 / B2 扁平文本 RAG / B3 完整 KG 完全可跑，且 **B2 是 01 与 02 都认定的"最关键 baseline"**（它同时回答"这是不是就是 RAG"）。
3. **已有系统：直接可比的不多，但机制可复现**。02 已核实：**KernelBlaster（NVlabs/KernelBlaster，Apache-2.0，含 test harness 与 repro pipeline）可直接跑**，是唯一可真实复现的强 baseline（GPU/KernelBench 路线）；QiMeng-Kernel 代码未发布；PRAGMA 与 MARCO 无公开仓库（只能用报告值或复刻机制）。此外 PRAGMA 在 KernelBench **CPU 与 GPU** 后端上报相对 Torch 2.81×/2.30×（arXiv:2511.06345），证明"CPU 上也做 kernel 生成评测"是成立的；QiMeng 系列在 RISC-V 上报告 OpenBLAS 的 211%–251%（QiMeng-GEMM AAAI'25；QiMeng-TensorOp arXiv:2505.06302），说明 CPU/RISC-V 方向有很高上界。
4. **"没有 baseline"的真实含义是"没有人在同一 benchmark 上比过"**。新任务定义的正常解法是：自建可复现 benchmark + 开源自建 benchmark + 复现最接近的机制 + 上界/下界/编译器三段参照。审稿人不会因为没有 SOTA 数字拒稿，只会因为**比较不公平、不可复现、指标可 hack**拒稿。
5. **公开 benchmark 是外部效度，不是主战场**：KernelBench（250 个 PyTorch 工作负载、`fast_p`，arXiv:2502.10517）与 TritonBench（184 个真实 Triton 算子，arXiv:2502.14752）是 GPU 生态；用户单机、知识源是 OpenBLAS CPU 实现，硬搬要 3–4 周移植且丢掉已有语料优势。但若**单卡 GPU 可用**，用 KernelBench L1 子集 + KernelBlaster 复现做 §5.4 的 X1/外部效度，是性价比最高的"有 baseline"证据（2–3 天，不阻塞主线）。

## 3. 任务定义：三个候选与推荐

### 3.1 候选对比

| 候选 | 定义 | 输入 / 输出 | 数据需求 | 可测性 | 工作量 | 结论 |
|---|---|---|---|---|---|---|
| **T1 硬件条件化/跨架构的算子优化代码生成** | 给定**功能正确但未优化**的算子实现 + 目标硬件画像 + 约束，生成该算子的**优化后 C 实现**（允许 intrinsics/OpenMP，禁止调用外部 BLAS） | 输入：`<op>_k.c`（或匿名化等价源码）+ `hardware_profile.json` + 接口契约 + 约束；输出：单个可编译 C 文件 | OpOptBench-45（现成语料，零新标注） | **强**：原生 x86 可测真实加速比；正确性可自动判定 | 中（harness 改造 1–2 周） | **推荐（主）** |
| T2 优化策略推荐 | 给定算子代码 + 硬件画像，输出**排序后的适用策略列表**（含参数建议） | 输入同上；输出 JSON 策略表 | "金标策略集"可从 RVV/CX/`param.h` **自动检测 + 人工抽检**得到 | 中（指标客观） | 低（无执行） | **推荐（RQ1 诊断）** |
| T3 跨架构代码迁移 | 给定通用 C 或 RVV 实现，生成 **CX（或 RVV）目标实现** | 输入：源实现 + 目标架构说明；输出：目标架构实现 | 现成（`openblas_cxtest` 流程） | **弱**：只有 QEMU，无真实硬件时间 | 低（流程现成） | **作 RQ3 泛化展示（非主指标）** |

### 3.2 推荐：T1 为主，T2 为 RQ1 诊断，T3 为 RQ3 泛化展示

理由：

- **数据零成本**：`*_k.c` 本身就是"专家写的通用 C 朴素实现"，天然是"用户输入的未优化代码"；`_<op>_dgc.c` 已经是"逐尺寸 pass/fail + 加速比"驱动；`param.h` 直接提供硬件—参数知识。
- **性能可测且口径干净**：x86-64 原生 wall-clock + roofline；RVV/CX 只承担"跨架构正确性与结构泛化"，不撒谎。
- **与定位 C 一致**：T1 的评测天然包含"同一策略从源架构（RVV/CX 专家实现）迁到目标架构（x86 AVX2/AVX512）后的正确性、保真度与增量"——这正是 RQ2/RQ3，也是 02 判定的**用户最独特、最可辩护的 delta**（"同算子 × 多架构"的语料绝大多数 LLM 组拿不到）。
- **避开单卡/时间陷阱**：不依赖 CUDA；3 个月内可完成；不把"超过 OpenBLAS"当目标（用户在 PPT 已明确"聚焦自动优化而非超过 OpenBLAS"），主指标是**差距闭合度 EGC**与**相对编译器/相对 B2 的增量**。

### 3.3 T1 的形式化定义

```text
任务实例 t = (op, F, I, P, C, S)：
  op : 算子标识（dgemm / daxpy / dtrsm …）
  F  : 通用 C 参考实现（输入，功能正确、串行、无 SIMD、无分块）
  I  : 接口契约（签名、参数语义、不变量：incx<0、uplo、trans、alpha/beta、lda≥m、原地别名）
  P  : 硬件画像 hardware_profile（ISA、向量位宽、lane 数、FMA、cache 层级/容量、核数、峰值 GFLOPS、实测带宽）
  C  : 约束（线程数=1 或 4；禁止 cblas_/openblas_/mkl/lapack；禁止 system()/文件/网络；禁止内联汇编；内存峰值 ≤ 参考 2×）
  S  : 知识上下文（由方法决定：空 / few-shot / 扁平文本 / KG 子图）

方法 m 输出单个 C 文件 g_{t,m}。
评分：编译 c(t,m)∈{0,1}；正确性 q(t,m,d)∈{0,1}，d∈{D1..D4}；时间 T(t,m)=20 次计时中位数（线程数固定，仅 q=1 时有效）。
```

### 3.4 明确"不做什么"

- 不追求在 GEMM 上超过 OpenBLAS；GEMM 类只报告**差距闭合度 EGC**。
- 不做 GPU/CUDA 主线、不做多机分布式、不做 LLM 微调（只做 prompt/检索侧方法；微调不在 7 个月预算内）。
- 不把 QEMU 时间当性能结论；不把"编译通过"当"优化成功"；不在测试集上调 prompt。

## 4. 数据与 benchmark：OpOptBench-45

### 4.1 构成

**数据源**：`openblas_newtest1/`（45 个算子，OpenBLAS 0.3.27.dev 抽取）。按 BLAS 层级分三组，用于分层报告与"跨族泛化"：

| 分组 | 数量 | 算子 | 主要优化策略类型 | RVV 专家 |
|---|---|---|---|---|
| L1 向量型 | 18 | damax damin dasum daxpby daxpy dcopy ddot dmax dmin dnrm2 drot dscal dswap idamax idamin idmax idmin zdotu | SIMD 宽度利用、多累加器、对齐/尾处理、inc≠1 分支、NaN/Inf 语义 | 部分 |
| L2 矩阵-向量型 | 17 | chbmv chemv cher cher2 chpmv dgemv dger dspmv dspr dspr2 dsymv dsyr dsyr2 dtpmv dtpsv dtrmv dtrsv | 分块、pack、上/下三角与 packed 遍历、秩 1 更新、重叠访问、预取 | 部分 |
| L3 矩阵-矩阵/LAPACK 型 | 10 | chemm cher2k cherk dgemm dgesv dsymm dsyr2k dsyrk dtrmm dtrsm | 微内核、寄存器分块、cache 分块（P/R/Q）、pack 布局、循环序、递归分块 | 部分 |

**精确覆盖事实**（来自 `openblas_cxtest/result/result.txt`，实验前用脚本复核）：21 个算子无 RVV 版本；19 个成功使用 CX 指令。

### 4.2 每个任务的目录规范（实验前生成 `OpOptBench/`）

```text
OpOptBench/tasks/<op>/
  task.yaml          # op, level, 签名, 语义不变量, 参数化范围, flops 公式, 参考实现路径
  input/generic.c    # 输入代码（来自 *_k.c，清洗掉 OpenBLAS 私有宏依赖）
  input/spec.md      # 人类可读语义说明（供 prompt；与 task.yaml 同源生成）
  ref/lib_ref.c      # 专家参照：x86 调系统 OpenBLAS 同签名函数；RVV 用提取的专家实现
  driver/bench.c     # 改造自 _file/benchmark/_<op>_dgc.c，输出 JSONL
  tests/gen_input.c  # 4 个隐藏分布的输入生成器（固定随机种子）
  tests/tolerance    # 每算子数值容差（参考实现自校准，§6.1）
```

`task.yaml` 示例（dgemm）：

```yaml
op: dgemm
level: L3
signature: "void dgemm(char transa, char transb, int m, int n, int k, double alpha,
                       const double* A, int lda, const double* B, int ldb,
                       double beta, double* C, int ldc)"
semantics: "C := alpha*op(A)*op(B) + beta*C"
invariants: ["transa/transb in {'N','T'}", "lda>=m if 'N' else lda>=k"]
flops: "2*m*n*k"
sizes: [{m:64,n:64,k:64}, {m:256,n:256,k:256}, {m:512,n:512,k:512}]
expert: {x86: "openblas-0.3.27", rvv: "task 自带 *_k_rvv.c 对应专家版本"}
```

### 4.3 从现有语料构造的 5 步（预计 8–10 人日）

1. **清洗输入**：把 `*_k.c` 中 `#include "common.h"`、`BLASLONG` 等私有依赖替换为 `typedef long blasint;` 等最小头，生成独立可编译的 `input/generic.c`（45 个，脚本 + 人工抽检 10 个）。
2. **改造驱动**：`migration_<op>` → `candidate_<op>`；`Ref` 侧 x86 调系统 OpenBLAS、RVV 链接提取的专家 `.a`；输出改 **JSONL**（一行一尺寸）。
3. **补隐藏分布**：现有驱动默认 1..200 步长 1（45 个算子均已有 `*_log.txt`/`.out`，流程跑通）；加 D2/D3/D4 输入与参数分支，不改原 pass 判定。
4. **固化容差**：每算子先跑"参考 vs 参考（不同循环序/不同编译器）"得误差基线，容差取 10×（§6.1），写入 `tests/tolerance`。
5. **profile 与 flops**：测每个 profile 的峰值与带宽（§6.7），flops 公式写入 `task.yaml` 供 roofline。

### 4.4 划分（防泄漏 + 泛化维度）

| 集合 | 规模 | 定义 | 用途 |
|---|---|---|---|
| **S1 已见族** | 12（daxpy, dscal, dcopy, dswap, ddot, damax, dasum, dnrm2, dgemv, dger, dgemm, dtrsv） | 其 RVV/CX 专家实现进入 KG 知识源（K-train） | in-domain 参照；验证"知识抓到了" |

防泄漏三条硬规则：

1. **知识源与测试集按算子名硬隔离**（S1 ∩ S2 = ∅），KG 只从 S1 的专家实现与 `param.h` 构建。
2. **匿名化对照（E7）**：prompt 去掉算子名/BLAS 签名，改纯语义描述并重命名函数与变量；若零样本匿名化后掉分而 KG 方法不掉，说明收益来自知识而非记忆 OpenBLAS 源码（正面证据）；反之如实报告"存在预训练记忆污染"。
3. **公开 benchmark 只做外部效度**，不参与任何 prompt 设计（本协议不做训练）。

### 5.5 公平比较的五条硬约束（写进论文的 Experimental Setup）

1. **同 LLM**：同一模型、版本、temperature、max_tokens；记录模型名与调用日期。

## 6. 指标定义与测量协议

### 6.1 正确性

| 指标 | 公式 | 说明 |
|---|---|---|
| 编译通过率 CR | `CR = (1/N) Σ 1[compile(g_t)=1]` | N = 任务×重复 |
| 功能正确率 FCR | `FCR = (1/N) Σ 1[⋀_{d∈D} q(t,d)=1]` | D={D1..D4} 全过才算正确 |
| 分布级正确率 | `FCR_d = (1/N) Σ q(t,d)` | 分 D1–D4 报告（暴露"标准过、边界挂"） |
| 数值误差 | `η = max_i abs(ĉ_i − c_i^ref) / (atol + rtol·abs(c_i^ref))`，要求 η ≤ 1 | 参考值 fp64/fp128 计算 |
| 容差自校准 | `atol_op, rtol_op = 10 × max(η) 在"参考 vs 参考"上的值` | 不同循环序/编译器两次参考互比，取 10×，写 `tests/tolerance` |
| 边界用例通过率 ECR | `ECR = 通过 D3 用例数 / D3 用例总数` | 单独报告 |
| **策略实现保真度**（RQ2） | `SIF = card(已实现策略 ∩ 推荐策略) / card(推荐策略)`，实现与否由策略检测器判定 | 对应 01 的 RQ2 "策略实现保真度" |

### 6.2 性能（只在原生 x86 上作为结论）

记号：`T_ref(t)`=输入代码 `-O2` ST 中位时间；`T_comp(t)`=C1；`T_lib(t)`=P1；`T(t,m)`=方法 m 生成代码中位时间。

```text
加速比（相对输入）   S_naive(t,m) = T_ref(t) / T(t,m)
相对编译器增量        S_comp(t,m)  = T_comp(t) / T(t,m)        ← 主报告口径（防"只赢在 O3"）
相对专家             S_lib(t,m)   = T_lib(t) / T(t,m)
差距闭合度 EGC       E = (T_ref − T) / (T_ref − T_lib)，截断 [0,1.5]   ← 仅对 T_lib < T_ref 的算子
几何平均加速比        GM_S = exp((1/|T|) Σ ln S_t)               ← 条件几何平均（只算正确任务）
fast_p             fast_p = |{t: q_t=1 且 S_comp(t) ≥ p}| / N，p∈{1.0,1.25,1.5,2.0}
端到端效用（含失败）   U = (1/N) Σ_t 1[q_t=1] · S_comp(t)         ← 失败记 0，防"简单任务拉高 GM"
峰值利用率           PeakPct = GFLOPS_measured / GFLOPS_peak(profile) × 100%
Roofline 效率        RE = T_roofline / T_measured，T_roofline = max(FLOPs/Peak, Bytes/BW)
```

- **主结论量**：`R = GM(B3) / GM(B2)`（配对、bootstrap CI），同时报告 `fast_1`、`EGC`、`U`、成本。
- 失败任务不参与 GM 但在 `U`/`fast_p` 记 0；两种口径都给，防止挑指标。
- 多线程：ST 与 4T 双口径；**4T 只在与 ST 同向时解读**（防"靠线程数取胜"）；`T_lib` 也按 1/4 线程分别测。
- Roofline 的 Peak/BW 必须**本机实测**（§6.7），不用厂商标称值。

### 6.3 知识质量（RQ1）

| 指标 | 公式/口径 | 测量方式 |
|---|---|---|
| 抽取微 F1 | 实体按 (span,type)、关系按 (head,rel,tail) 严格匹配 | 人工标注 **150 条金标**（与 01 的 RQ1 口径一致；从 S1 的 RVV 与 `param.h` 抽样） |
| 对齐 P/R/F1 | 200 实体对的 pair-level | 双人标注，报告 Cohen's κ（目标 ≥0.75） |
| **跨架构同一策略合并准确率** | 同一策略在 x86/RVV/CX 三种表述下被正确合并的比例 | 对应 01 的 RQ1 指标 |
| **来源可追溯率** | 每个实体/策略能回溯到源文件+行号的比例 | 对应 01 的 RQ1 指标（Schema 需带 provenance） |
| 去重率 | `δ = 1 − card(E_canonical)/card(E_raw)` | 自动 |
| 覆盖率 | `Cov = card({(op,strategy)∈Gold 且 dist_G ≤ 2}) / card(Gold)` | Gold 来自策略检测器 |
| 连通性 | 最大连通分量占比 + 平均度 | 自动 |
| 冲突识别 F1 | 预定义冲突对 50 对人工判定 | 人工 |

**策略金标的客观来源**（T2/RQ1 关键，避免主观标注）：对每个算子的专家实现（`*_k_rvv.c`/CX 版）用**规则/AST 检测器**判定所用策略集合（RVV intrinsic→向量化；`vsetvl`→可变长；循环步长 2/4/8→展开；pack/copy→分块；prefetch→预取；`#pragma omp`→并行；`inc_x` 分支→步长特化；tail 循环→尾处理），再由人抽检 30% 修正。检测器可复用到 45 算子，成本 1–2 人日。

### 6.4 检索质量（T2 主指标）

```text
P@k = |Retrieved_k ∩ Gold| / k；R@k = |Retrieved_k ∩ Gold| / |Gold|
nDCG@k = DCG@k / IDCG@k，DCG@k = Σ_{i=1..k} rel_i / log2(i+1)，rel ∈ {0,1}
MRR = (1/|Q|) Σ 1/rank(第一条命中)
SAR（策略可适用率）= 判为"对该算子+该硬件确实适用"的 top-k 策略数 / (k×|Q|)
PIV（参数有效性）= 生成参数落在 KG 参数区间的比例
PNR（参数近优率）= |log(p_gen/p_opt)| ≤ log(1.5) 的比例（抽 10 算子做参数网格搜索得 p_opt）
```

### 6.5 成本

```text
Token 成本 C_tok = Σ (prompt_tokens×p_in + completion_tokens×p_out)（记录实际账单/用量）
每任务成本 C_task = C_tok / N_correct（成功一个正确解的成本）
端到端时延 Latency = 生成时延 + 编译验证时延（分别报告）
人工代价：知识抽取工时、标注工时（如实报告）
```

### 6.6 主/次指标与 RQ 映射（预注册，防 p-hacking）

| RQ | 主指标 | 次指标/机制指标 |
|---|---|---|
| RQ1 知识表示与质量 | 抽取 F1、对齐 F1、跨架构合并准确率、来源可追溯率 | 去重率、覆盖率、连通性、冲突 F1 |
| RQ2 迁移保真度与增量 | **R = GM(B3)/GM(B2)**（配对检验）+ FCR | S_comp、fast_1、EGC、U、SIF、PIV、成本 |
| RQ3 边界条件与归因 | 可迁移性分层表（架构无关 vs 架构特定策略的增量差）、**谓词过滤的预测准确率**（硬件谓词预测迁移成败的 precision/recall） | 失败归因分类（条件不满足/生成能力不足/参数错配）、A4/A5 的 ΔGM |

- 主对比（确证性）：**B3 vs B2**，单一检验，不校正；消融家族（A1–A12）用 Holm–Bonferroni。
- 每个指标在论文中给定义、N、重复次数、统计量（中位数+IQR 或均值±95%CI）。


**计时规程**：

1. 每 (task, method, size)：5 warmup + 20 次重复取**中位数**；RSD>3% 整组重测（≤3 次），仍不稳则该任务标"测量不可靠"并说明。
2. 计时统一 `clock_gettime(CLOCK_MONOTONIC_RAW)`（现有 `bench.h` 用 `CLOCK_REALTIME` 会被 NTP 跳变污染；`benchmark_common.h` 用 `clock()` 是 CPU 时间，**多线程失真，禁止用于计时**）。
3. 每轮重填输入（防记忆化），用 `volatile`/屏障防优化掉循环。
4. ST：`OMP_NUM_THREADS=1` + `taskset` 单核 + 生成代码禁止 OpenMP/pthread。
5. 4T：`OMP_NUM_THREADS=4`，`num_threads(4)` 显式；baseline 同线程数。
6. 隔离子进程编译运行，超时 60 s（QEMU 300 s），内存上限 2× 参考（cgroup/`ulimit -v`）。

**Roofline 实测（一次性，1 天）**：

```text
Peak(profile) = cores × f_eff × lanes_DP × 2（FMA），f_eff 取实测稳定频率
BW(profile)   = STREAM-triad 实测 GB/s（ST 与 4T 各测）
每 (op,size)：FLOPs 来自 task.yaml；Bytes 按读入+写出元素数估算（标注为估算口径）
```

**反 reward-hacking 检查（每次评测自动执行）**：

| 检查 | 方法 | 处理 |
|---|---|---|
| 调用库函数 | 正则+AST（`cblas_` / `openblas_` / `mkl_` / `lapack_` / `dgemm_` 等符号）+ 编译后 `nm/ldd` | 命中即 fail |
| 多进程/线程越权 | 扫描 `pthread_create` / `fork` / `system` / `popen` / `dlopen`；ST 口径 `strace` 计 clone | 命中即 fail |
| 硬编码尺寸/输入 | D2/D3 隐藏尺寸与数据；扫描可疑常量比对隐藏尺寸表 | 告警 + 人工复核 |
| 记忆化/跳过计算 | 每轮重填输入 + 时间随尺寸单调性 + 独立种子复跑 | 异常则整组作废 |
| 降精度偷速度 | D4 极端值 + 容差 + 检查 float/double 混用 | 由 FCR 捕获 |
| 内存爆炸换速度 | 峰值 RSS / 参考 RSS（KernelBench-Verified 做法） | >2× 标注，主表同时报内存比 |
| 只对对齐尺寸优化 | D2 中不规整尺寸占比 ≥25% | FCR 分分布报告 |

**防泄漏/防污染**：E7 匿名化（§4.4 规则 2）；prompt 只在 dev 集（S1 的 3 个算子）上调，测试集不参与任何 prompt/参数选择；prompt 版本存档并打 SHA256。

### 7.3 "图结构本身带来增量"的三重证明（审稿人最可能的攻击点）

1. **同内容异构（A1 + E3）**：把 B3 子图的**同一批三元组**线性化成文本（B2），token 差 ≤10%，只改组织形式。B3 > B2 ⇒ 结构有独立贡献。**核心对照。**
2. **同构去内容（A5/A6 + A4）**：保持 KG 组织，删"适用条件/硬件参数"或把参数换成另一 profile。掉分 ⇒ 贡献来自"条件—参数绑定"这一结构语义，而非"多给了词"。
3. **同规模随机子图（A3）**：同 token 预算的随机知识子图。B3 > B10 ⇒ 贡献来自"相关的图结构"而非上下文长度。

加固两点：**等尝试预算反馈基线（A10/B12）**证明不是多轮迭代的功劳；**匿名化（E7）**证明不是预训练记忆 OpenBLAS 源码。

论文表述建议："我们不是把 KG 当检索库，而是把**策略—条件—参数—硬件**的绑定结构作为可执行约束注入；A1/A5/A4/A3 表明，去掉结构、去掉条件、错绑硬件、换成无关子图，性能分别下降 X%/Y%/Z%/W%。"

## 8. 统计与可复现

### 8.1 实验单元与重复

- 单元：`(task, method, seed, size)`；报告时先对 size 取几何平均得 per-task 值，再做配对检验（主）；另用 LMM 做 (task,size) 级次检验。
- 重复：LLM 采样 3 次（`temperature=0.2`，`top_p=1.0`；固定 seed 或记录不固定）；计时 20 次取中位数；QEMU 正确性 3 次（确认非 flaky）。
- 排除规则（预先声明）：编译超时/运行超时/超内存 → 记 fail（不剔除，防幸存者偏差）；RSD>10% 且 3 次重测仍不稳 → 标记并单独报告。

### 8.2 检验与效应量

```text
配对检验：Wilcoxon signed-rank（双侧，α=0.05），配对单位 = task 的 log S_comp
效应量：Cliff's δ = (#(x>y) − #(x<y)) / (n_x·n_y)，|δ|：0.147 小 / 0.33 中 / 0.474 大
几何平均比：R = exp(mean(ln S_{m1}) − mean(ln S_{m2}))，bootstrap 10,000 次给 95% CI（按 task 重采样）
主检验：R 的 95% CI 不含 1 且 p<0.05（与 01 的 G2 判据一致：效应 ≥10% 且 CI 不跨 0）
2×2 交互：log S ~ 组织 + 内容 + 组织×内容 + (1|task)，LMM
```

### 8.3 多重比较与预注册

- 消融家族（A1–A12）Holm–Bonferroni（家族内 α=0.05）；主对比 B3 vs B2 单独作确证性检验，不校正但只此一个。
- **预注册**：开跑前把"主指标、主对比、N、排除规则、分析脚本"写进 `prereg_v1.md` 并记 SHA256；跑完不得改主指标；探索性分析单独标注。
- 原始数据（JSONL）、分析脚本、prompt 版本、KG 快照、生成代码、编译日志全存档。

### 8.4 功效（说明 N 的选择）

- 配对 Wilcoxon，双侧 α=0.05：N=45 可检出 |δ|≈0.42（80% 功效）；S2-only（N=24）只能检出大效应。
- 因此**主结果以 S2=24 为"泛化"主表，显著性检验用 S1∪S2=36（或 45 合并）**（同属 OpenBLAS 算子、同 harness、同 profile），附录给 S2-only。
- 若 pilot（20 算子）显示 B3/B2 的 GM 比 <1.03，则当前 N 无法判定 → 扩 N 或改主任务（§9.3）。

### 8.5 可复现工件清单（release 包）

```text
1. OpOptBench-45（task.yaml、input、driver、tests、tolerance；D3/D4 隐藏用例不公开具体种子）
2. 全部 prompt 模板与版本（含 token 计数脚本）
3. KG 快照（JSON/CSV 三元组 + 构建脚本 + 抽取/对齐原始输出）
4. 每次生成代码 + 编译/运行日志 + JSONL 结果 + 统计脚本
5. env_report.json（机器、编译器、OpenBLAS、调频策略）
6. Dockerfile（x86 侧）+ RISC-V/CX 工具链版本说明
7. 一键复跑脚本：make bench-main / make ablations / make tables
```

### 9.3 负结果预案（6 种情形 → 诊断 → 行动）

| 情形 | 现象 | 最可能原因 | 诊断实验 | 行动/Plan B |
|---|---|---|---|---|
| N1 | **B3 ≈ B2**（结构无增量） | 知识内容本身是瓶颈，或扁平文本已含全部信息 | 查 B2 的 token 与命中策略数；跑 A5/A6 看 B3 是否也掉分 | 主线改"**内容 vs 结构**的实证：结构化在什么条件下才有用"；T2+检索协议作主贡献（对应 01 的 Plan B：B 定位实证论文） |
| N2 | **B3、B2 都 ≤ C1**（被编译器打败） | 任务太"编译器友好"（L1 向量型），或 prompt 不足 | 分层看 L1 vs L2/L3 的 GM；看生成代码是否只是复制原代码 | 主结果聚焦 L2/L3（分块/重排）；加逐步策略引导；仍不行转 N1 |
| N3 | **FCR 太低（<50%）** | 模型写不出正确 BLAS 语义（尤其复数/三角求解） | 抽 20 个失败看错误类型（编译/数值/边界） | 缩任务（L1+L2 实数 20 个）；接口契约显式化；允许 1 轮编译错误反馈（等预算）；换更强模型（附录"模型规模效应"） |
| N4 | **方差过大无法判定** | LLM 采样方差 + 计时噪声 | 方差分解（task/seed/size） | 主对比条件加到 5 次重复；per-task 中位数；改用单调一致性判据（B3 在 ≥65% 任务上优于 B2） |
| N5 | **硬件条件化无效（A4/A5 无差异）** | 参数知识未被使用，或生成代码没用 intrinsics | 查生成代码 intrinsics 使用率、参数出现率 | 创新点 3 收窄为"策略+实施步骤"；硬件参数改为可选提示并如实报告；RQ3 的"谓词预测力"作主结论 |
| N6 | **跨架构（RVV/CX）大面积失败** | 模型不熟 RVV intrinsics；QEMU/工具链限制 | 统计失败类型（编译 vs 正确性） | 跨架构降级为"结构泛化 + 案例研究"；主结论只依赖 x86；论文明确说明 |

**负结果写作原则**：预注册分析计划 + 完整负结果比勉强凑的正结果更有价值；审稿人接受"结构化知识在 X 条件下无效、在 Y 条件下有效"的边界结论，但不接受"结果模糊仍宣称有效"。

## 15. 不确定/需 Lead 决策的点

1. **LLM 选择（第一优先）**：用户原型用 DashScope `qwen-plus`；建议主模型换为代码能力更强的 qwen3-coder 系列或本地 Qwen2.5-Coder-14B/32B。需确认：是否有 GPU 可本地部署（可复现最佳）、API key/预算、能否固定版本（防漂移）。
2. **ARM 是否存在（影响定位 C 的强度）**：02 提到用户有 x86/ARM/RISC-V 语料，但本次只确认到 `common_arm64.h` 头文件与 `cx-gcc` 的 ARM 头，**未见 ARM kernel 源码或 ARM 交叉工具链**。若 ARM 真机/语料存在，应把 ARM 加入 S4/S5（跨架构轴从 3 个变 4 个，RQ2/RQ3 更强）；若不存在，跨架构轴 = x86-v2/v3/native + RVV + CX，需在论文中如实说明。
3. **RISC-V 真机**：`make_rvv_risc64.sh` 注释指向 SpacemiT K1 / Banana Pi F3。若有板子，RVV 可做原生性能；若没有，RVV 只报正确性+结构指标（本协议默认）。
4. **CX 是否有真实硬件**：当前只有 `qemu-cx`。若纯模拟器，CX 只能作"结构泛化案例"，不进性能主表。
5. **x86 服务器规格**：CPU 型号/核数/是否支持 AVX512/能否锁频/是否有 root 改 governor。决定 E5 用 v2/v3/native 还是 haswell/skylake 手写 flag。
6. **主实验是否合并 S1/S2/S3**：为统计功效建议 45 个算子合并检验、S2 单独报告；若导师要求"只看未见算子"，功效会降到只能检出大效应，需把重复从 3 提到 5。**需 Lead 与导师拍板。**
7. **是否做 KernelBench + KernelBlaster 外部效度（E8）**：需 GPU 与 2–3 天；与 12 周投稿倒排冲突。建议：有 GPU 则做时间盒版，无 GPU 标"Future Work"。**需 Lead 决定。**
8. **投稿节点确认**：01 判断"小论文 2027-01 底前必须投出"；若导师另有安排（如先投中文期刊/会议），排期需相应前移/后移。
9. **双人标注可行性**：策略金标与对齐金标需第二名标注者；若无人力，全用"自动检测+单人抽检"，论文如实声明（削弱但不否定结论）。
10. **代码可得性**：KernelBlaster/GEAK/Xe-Forge/AutoTriton 已开源（02 核实）；PRAGMA/MARCO 无仓库；QiMeng-Kernel 代码未发布。若后续 PRAGMA 代码公开，X1 改为直接复现（+2 人日）。
