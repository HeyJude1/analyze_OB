# 31 硬件画像从哪来，以及图谱的"泛化"到底指什么

> 2026-11-16｜回答两个问题：① 硬件画像怎么得到、要不要 6 台机器；② 只做过滤是不是把图谱用成了知识库，泛化怎么落地。
> 写法仍按"定义 → 数据 → 边界"。

---

## 0. 两个短答

1. **不需要 6 台机器**。需要 6 份"能力档案"；档案分三档来源（规格 / 工具链 / 实测），**只有"证据"需要真机**。
2. **你的批评是对的**：只做"命中/不命中"的过滤，图就是带约束的知识库。**泛化不来自"图里存了什么"，来自"在图上的运算"**——抽象、类比、组合、参数实例化、反事实诊断。只存不算，就没有泛化。

---

## 1. 硬件画像怎么得到

### 1.1 三档来源（按可靠性递减，按成本递增）

| 档 | 来源 | 能填的字段 | 需要机器吗 |
|---|---|---|---|
| **A 规格** | ISA 手册、芯片/板卡 datasheet、白皮书 | ISA/feature、VLEN、向量寄存器数、核数、cacheline（通常）、cache 容量 | 不需要 |
| **B 工具链** | 编译器宏、`lscpu`、sysfs、`/proc/cpuinfo` | 实际编译选项、宏定义、cache 层级与容量、NUMA、频率标称 | 需要一台能跑该工具链的机器（交叉编译 + 目标 sysfs 也行） |
| **C 实测** | 微基准 | 实际频率、peak FLOPs、STREAM 带宽、cache 延迟/带宽、真实 VLEN | **需要真机** |

具体命令（可直接抄）：

```bash
# x86 / ARM 通用
lscpu
getconf LEVEL1_DCACHE_LINESIZE
cat /sys/devices/system/cpu/cpu0/cache/index*/coherency_line_size
cat /sys/devices/system/cpu/cpu0/cache/index*/size
gcc -march=native -Q --help=target | grep -E 'avx|fma|sve|neon'
gcc -march=native -dM -E - </dev/null | grep -E 'AVX|FMA|SVE|NEON'

# RISC-V
cat /proc/cpuinfo                      # isa 字符串：rv64imafdcv...
riscv64-linux-gcc -march=rv64gcv -dM -E - </dev/null | grep RISCV
riscv_hwprobe                          # Linux 6.4+，探测 VLEN/扩展
# VLEN 探针：vsetvli t0, x0, e64,m1 后读 vl；或跑一个 vle64 循环
```

### 1.2 6 个 profile 的现状（`schema/hardware_profiles.yaml`）

| profile | 档位 | 真机 | 缺什么 |
|---|---|---|---|
| x86_avx2 | A+B（freq/peak 未测） | 有（工作站） | peak/stream、实际频率 |
| x86_avx512 | A+B | 同上（若 CPU 支持） | 同上 |
| k1_rvv256 | A+B（freq 标称 1.6） | 有（K1 板） | peak/stream、锁频确认 |
| qemu-riscv64 | A | 模拟器 | 不可测性能（`measure_env=qemu`） |
| arm_neon | A | **无** | 全部实测项 |
| arm_sve | A | **无** | 全部实测项 |

**结论**：你现在是"2 台真机 + 1 个模拟器 + 3 份规格档案"。这完全够用，前提是：
- 规格档的 profile **只用于过滤与参数推导**，不用于性能结论；
- 每条 profile 字段带 `source`（手册章节 / 命令输出 / 实测脚本），拿不到的写 `null` 并标 `note`（你的 YAML 已经是这个约定）；
- 论文里把"能力模型"和"测量平台"分开表述。

### 1.3 要不要凑 6 台机器？

不要。按 claim 需要：

| 你想说的 | 需要的机器 |
|---|---|
| 跨架构知识可迁移（过滤/参数推导） | 不需要真机，规格档即可 |
| 生成的代码在 x86/RVV 上正确且更快 | x86 + K1 两台 |
| NEON/SVE 上的性能结论 | 需要对应真机；没有就别写性能，只写"知识覆盖" |
| QEMU 结论 | 只能写正确性/相对趋势，不能写绝对性能 |

## 2. 只做过滤，确实是知识库

### 2.1 把话说清楚

过滤的语义是：

```text
match(q, K) = { s ∈ S | cond(s) ⊆ features(q) ∧ hw(s) ∋ h(q) }
```

有就返回，没有就空。这是**闭世界查询**，和 SQL/规则引擎没有本质区别。你现在七步检索的第 3、4 步就是它。**这一步是必要的，但它只是下限。**

图的优势不在"存了 262 条卡"，而在"卡之间有边、有抽象层、有约束、有证据"，于是可以对卡做**运算**：

```text
答案集 = Closure(S, {抽象, 类比, 组合, 参数实例化, 验证})
```

其中 `Closure` 里的新方案**不在 S 里**——这才是泛化。区别可以用一句话概括：

> 知识库回答"哪条知识匹配"；图谱回答"在约束下，能构造出什么方案"。

### 2.2 图谱的六级用法（从查表到泛化）

| 级 | 问句 | 图上的操作 | 需要 agent | 泛化类型 | 可测指标 |
|---|---|---|---|---|---|
| L1 查表 | "哪张卡匹配？" | 类型/条件过滤 | 否 | 无 | SAR、R@k |
| L2 参数 | "这张卡在这个硬件上参数取多少？" | profile + 推导函数 θ | 否 | 参数泛化 | PNR、PIV |
| L3 组合 | "哪几条能一起用、顺序如何？" | COMPOSES_WITH / CONFLICTS_WITH / 预算 | 弱 | 组合泛化 | 编译率、FCR |
| L4 类比 | "没有这张卡，最近的是什么？" | GENERALIZES / ANALOGOUS_TO / 模式相似 | 是 | 跨算子、跨架构 | 留出算子 FCR/EGC |
| L5 诊断 | "为什么失败？改哪条？" | 失败→条件/证据反查；反事实 | 是 | 修复泛化 | 修复成功率 |
| L6 探索 | "试一个没人写过的方案" | 提议→查图→验证→写回 | 是 | 开放世界 | 新方案有效率/成本 |

你现在的实现停在 **L1**（部分 L2：参数合并，但没有推导函数）。L3–L6 基本没有。**"图没发挥优势"的根因不是图不行，是只用了 L1。**

### 2.3 一个具体例子：留出算子 `symv`

现状（真实数据）：

- `symv` 有 **4 条策略**（tile/vectorize×3），但 **`Operator` 节点没有注册**、**没有任何 `OPERATOR_HAS_PATTERN` 边**；
- 结果：3 条完全不可达，1 条只能从 `GENERALIZES` 侧门被看到；检索 `symv` 直接 0 命中。
- 这就是你说的"没有就检索不出来"的教科书案例——**而且是配置漂移造成的，不是知识不存在**。

用 L2–L4 的做法：

```text
① 修 S0：注册 Operator(symv)，补 pattern（matvec core / diag 复用）
② 匹配：pattern=矩阵向量核心 且 structural=symmetric 且 dtype=d
③ 近邻：gemv（一般 matvec）+ symm（对称 matmul）→ 取 vectorize / tile / tail_handle 抽象
④ 参数：K1 profile：VLEN=256, SEW=64 → VL=4；LMUL≤8；32 寄存器
        → (LMUL, reg_block) 由预算算，不从旧卡抄
⑤ 约束：REQUIRES(RVV 1.0) ⊆ profile.isa；检查 CONFLICTS（tile×vectorize 有 14 条冲突边）；
        寄存器预算 ≤ 32×(1-reserve)
⑥ 组合成方案：向量化核心 + 行分块 + 尾部掩码
⑦ 执行验证：编译 → 正确性（D1–D4）→ 计时；失败则 L5 诊断（哪条条件/哪条策略）
⑧ 写回：通过门控后成为新卡（带证据），第二部分维护
```

这条链上，**每一步都在用图里不同的东西**：pattern 边、characteristic、抽象边、profile、ISA 边、冲突边、证据。答案不是"检索出来的"，是"构造出来再验证的"。

### 2.4 参数泛化：算出 4，而不是查到 4

示意公式（**未实测校准，只说明"计算"与"查表"的区别**）：

```text
每向量元素数 E = vector_bits / 64            # double
可用寄存器  R = vector_regs - reserve(≈4)
最大分组    M = min(lmul_max, floor(R / A))    # A = 累加器组数
展开因子    U = clamp(floor(R / (A·LMUL)), 1, 8)
块大小      B = 2^floor(log2(sqrt(L1_bytes / (3·8))))   # 三矩阵流
```

- AVX2：`vector_bits=256, E=4, vector_regs=16, LMUL=1` → R=12，U 上限 12，实际受调度限制取 4–6；
- K1：`vector_bits=256, E=4, vector_regs=32, LMUL≤8` → R=28，LMUL=8 时 A≤3，LMUL=4 时 A≤7。

同一张"寄存器分块"卡，在两个 profile 上实例化出不同 `(LMUL, A, U, B)`——**这就是参数泛化**，也是"图谱 + 硬件画像"相对纯文本知识库的硬差异。

### 2.5 Agent 在这里干什么

不是"让 agent 读图然后写代码"，而是把图当**环境/工具**：

```text
任务 → 解析(算子/特征/硬件)
     → 查图：精确命中？ 否 → 最近族（pattern+characteristic 相似）
     → 提议：抽象策略 + 参数实例化 + 组合
     → 查图：约束/冲突/预算/证据 是否支持？
     → 生成 → 编译/运行（外部 oracle）
     → 失败 → 诊断（反查条件/证据）→ 修
     → 成功 → 写回（门控 + 版本）
```

图的接口应该只有六七个，不要做成"把整张图塞进 prompt"：

```text
query_exact(op, hw, features)         -> cards
nearest_family(pattern, char, k)      -> cards + 相似理由
abstract_of(card)                     -> 抽象策略
params_for(card, profile)             -> 实例化参数
check(plan)                           -> 约束/冲突/预算 报告
evidence_for(card)                    -> 证据
write_candidate(card, trace)          -> 门控后入库
```

**关键**：agent 负责"提议与搜索"，图负责"约束与证据"，编译器/运行时负责"裁决"。三者缺一，泛化就会退化成"LLM 自由发挥"或"知识库查表"。

### 2.6 泛化必须可测（否则是口号）

| 泛化类型 | 实验 | 指标 | 对照 |
|---|---|---|---|
| 跨算子 | 6 个留出算子（S2） | FCR / EGC / R@k（策略推荐） | 无图 / 扁平文本 / 只 L1 |
| 跨架构 | x86 学 → RVV 用；RVV 学 → x86 用 | 参数误差、EGC、失败归因 | 直接抄参数 / 重推导 |
| 组合 | 只在训练集出现过的策略，组合出新方案 | 编译率、正确率、SIF | 单策略 / 随机组合 |
| 参数 | 预测参数 vs 网格最优 | PNR、PIV | 固定默认值 |

## 3. 要补的东西（按优先级）

1. **注册与对齐**：把 `symv` 这类"有策略没算子"的清掉；补 `ANALOGOUS_TO`（当前 0 条）与 `INSTANCE_OF` 的实例边。
2. **参数推导函数**：把 `derived_from` 从注释变成可执行函数（`params_for(card, profile)`），并记录推导依据。
3. **最近族检索**：pattern+characteristic 的相似度接口（不是向量相似，是结构匹配）。
4. **组合与预算检查**：已有冲突边 14 条、组合边 4 条——太少，需要从实现里补。
5. **执行闭环**：生成→编译→运行→回写；`FailureCase` 现在是 **0 条**，这是最大的空白。
6. **构造轨迹**：现在只存检索 trace；要存"构造轨迹"（用了哪条抽象、哪次参数推导、哪次冲突消解、哪次失败）。

## 4. 边界（必须写进论文）

- 图**不能发明**没人写过的策略。泛化 = 在结构约束下的**重组 + 参数化 + 类比 + 验证**，不是无中生有。
- 开放世界靠"agent 试错 + 执行验证 + 写回"扩展，不靠检索本身。
- 没有执行验证的"泛化"只是文本改写；没有图的"泛化"只是 LLM 自由发挥。
- 所以论文的主张应是：**"图提供可验证的构造空间，agent 在其中搜索，执行器裁决"**——而不是"图能自动泛化"。
