# 27 建图路线选择：语义图、可执行图，还是混合

> 2026-11-16｜针对论文题目《基于知识图谱的大语言模型自动生成高性能算子代码方法研究》
> 结论：**选混合（C1）——可执行图为主键，语义注解为辅；不是纯 LLM 语义图，也不是纯规则表。**

---

## 0. 先把"建图方式"拆成两个轴

你其实在问两件不同的事，混在一起会选错：

| 轴 | 选项 | 决定什么 |
|---|---|---|
| **轴 1：知识表示** | 语义三元组（analyze_OB1） / 可执行策略卡（kg_agent） / 混合 | 论文的**上限**：图能不能支撑"选择→生成→验证" |
| **轴 2：构建过程** | LLM 端到端 / 规则差分 / 子代理流水线（kg-build） | **可复现性与工作量**：能不能重跑、能不能校验 |

**轴 1 决定论文成不成立，轴 2 决定你累不累。** 子代理、skill、workflow 都是轴 2 的工具，不能替代轴 1 的选择。

---

## 1. 三个候选

| | A 语义图（analyze_OB1） | B 可执行图（kg_agent） | **C 混合（推荐）** |
|---|---|---|---|
| 实体 | 7 类概念（策略/原理/模式/参数/硬件/示例） | 12 类（策略/模板/参数/证据/来源/硬件…） | B 为主 + A 的原理/示例做注解 |
| 关系 | 12 类语义关系 | 14 类约束关系（APPLIES_WHEN/REQUIRES/CONFLICTS…） | B 的关系 + ANALOGOUS_TO/原理注解 |
| 条件 | 自然语言散文 | 闭集谓词，可求值 | 谓词（主）+ rationale（注） |
| 溯源 | 文件名 + 代码片段 | 文件 + 行号 + sha256 | 行号（主） |
| 证据 | LLM 的"性能影响"散文 | 证据节点（QEMU/真机） | 证据节点 + 标注 `unverified` 的声明 |
| 检索 | 向量 + 图遍历 + Agent | 类型化约束检索（七步） | 约束检索为主；语义层做可选召回 |
| 构建 | LLM 全链 | 差分 + 规则 + 模板 | 差分/规则抽事实，LLM 只注解 |

实测数字（你自己的数据）：A 一轮产出 **206 条策略 / 805 条关系**，但规范化后只有 **61 条（23%）** 进入可执行图；这 61 条**贡献了 C5 全部 6 组重复**，且没有一条有行号。

## 2. 为什么不是 A（纯 LLM 语义图）

**理由一：A 的知识，LLM 本来就会。**
"循环不变量外提""数据级并行""减少访存"——这些是教科书优化常识，已经在大模型权重里。检索出来喂回去，增量接近零。你论文要证明"图有用"，就必须给模型**它不知道的东西**：这个内核在第 46–213 行怎么写的、AVX2 上 LMUL/SEW 取多少、K1 上实测多少。这些只有 B/C 有。

**理由二：A 无法评测。**
没有行号 → 无法核；条件是散文 → 无法过滤；效果是 LLM 散文 → 无法验。你的"知识质量"一章会退化成"LLM 自评"，审稿人一问就塌。而 B/C 的每个字段都能出指标（SAR、PIV、溯源率、覆盖矩阵）。

**理由三：A 的检索退化成向量 RAG。**
没有可求值条件，就只能"嵌入召回 + 塞 prompt"，方法学上就是 GraphRAG 的一个特例。审稿人会说"你这不就是 RAG 吗"。B/C 的约束检索才是可辩护的差异点（你自己的 probe：图检索 SAR 100%，BM25 在 dgemm 上只有 20%）。

---

## 3. 为什么也不是纯 B（只有可执行图）

**理由一：太薄，撑不起"知识图谱"三个字。**
纯 B 更像"规则库 + 索引"。要有图的味道，至少需要：多跳关系（策略→条件→硬件→证据）、类比边（跨架构 ANALOGOUS_TO）、原理层（为什么）。这些恰好是 A 的强项。

**理由二：不能解释。**
答辩必问"为什么推荐这条"。B 能答"因为 stride=1 且 AVX2 支持 FMA"，但答不了"这条策略的原理是什么、代价是什么"。注解层便宜（1–2 天映射），能把这个问题补上。

**理由三：跨架构迁移缺语义。**
B 的 `parameterized` 策略有 30 条，但"为什么 x86 的展开因子不能直接搬到 RVV"需要原理性解释；这层解释来自 A。

## 4. 为什么 C 最适合这个题目

### 4.1 题目要的是"KG 服务生成"，不是"KG 构建方法"

题目是《基于知识图谱的 LLM 自动生成高性能算子代码方法研究》——**图是手段，生成是目的**。所以：

- 图的评价标准 = 它让生成变好了多少（FCR/EGC/SIF/PIV），不是它自己多漂亮；
- 构建方法只能是**支撑性贡献**（第 3 章），不能当主贡献；否则你要和 GraphRAG/KGGen/AutoSchemaKG 正面竞争，硕士半年做不过。

### 4.2 C 的三个贡献点都能落地

1. **表示**：条件 + 参数 + 模板 + 证据 + 来源的五元组策略卡（B 的骨架 + A 的注解）；
2. **选择**：约束引导的知识选择（七步检索），可回放、可消融；
3. **维护**：轨迹 → 门控 → 版本化（第二部分），注解层也能被更新。

### 4.3 复用你已有的 77%

B 的 201 条规则策略、七步检索、E09 结果、69 个测试都能直接用；A 的 61 条不用扔，降级成注解即可。**换路线等于重做半年**，这是硕士论文最大的风险。

### 4.4 与文献对齐

- 和 GraphRAG/LightRAG 的区别：它们在"文档语料 + 全局问答"上工作，你在"代码差分 + 硬约束选择"上工作；
- 和 GraphJudge/OneKE 的区别：它们校三元组，你校策略卡字段（上一轮的 C1–C9）；
- 和 KGGen/iText2KG 的关系：借它们的消歧纪律，不借它们的抽取路线。

## 5. C 的最小实现（C1）与可选扩展（C2）

### C1（建议，2 周内可完成）

```text
可执行层（主键）
  OptimizationStrategy: conditions(谓词) + parameters + template + evidence + provenance(行号)
语义层（注解，不参与过滤）
  properties.rationale / trade_offs / aliases / principle_id
  可选：OptimizationPrinciple 节点 + EXPLAINS 边
检索：仍走七步；注解只进 prompt 的"解释段"，不参与打分
```

工作量：
- 把 61 条 `_a` 策略的 rationale/示例按（算子+动作+层级）映射到规则策略：1–2 天；
- 剩余无对应的，保留为独立节点并标 `status=legacy`；
- 不改检索、不改实验，只在 pack 里多一个 `explanation` 字段。

### C2（可选，做成一个实验或"未来工作"）

**双层召回**：语义层做高层召回（自由文本需求、未见算子），可执行层做低层过滤。这对应 LightRAG 的 low/high-level 思路，但过滤是可求值的。

适合场景："把这个 kernel 弄快一点"这种没有算子名的请求。**主实验不需要它**，别为它加班。

## 6. 一张决策表

| 你的目标 | 该选 |
|---|---|
| 论文主线：KG → 代码生成，要可测、可消融 | **C1** |
| 想强调"AI 建图"本身，去投 KG 构建方向 | A（但要换题目、换评价体系，风险高） |
| 只想快速出图、做 demo | A |
| 已有 pipeline 不想动，只补解释 | B + 注解（= C1 的轻量版） |
| 想做自由文本需求 / 未见算子 | C2 |

**反例条件**：如果你发现"注解层"对生成没有任何影响（消融里 ΔFCR≈0），那就退回纯 B，把注解只当论文里的解释材料——这也是一个诚实结论。

## 7. 论文里怎么写（可直接用）

第 3 章定位：

> 本文的知识图谱不是从文档中端到端抽取的语义图，而是**以差分与静态分析为事实来源、以策略卡为知识单元、以行号与证据为可追溯性保障**的可执行知识图谱；LLM 只参与语义注解与解释，不参与事实生成。

贡献句：

> 提出一种"可执行层 + 语义注解层"的双层知识表示：可执行层用闭集谓词、参数域与证据约束支撑检索与生成；语义注解层提供原理、代价与跨架构类比，用于解释与迁移分析。

实验对应：
- 第 3 章：知识质量（120 条金标准 + 命名/参数/重复检查）；
- 第 4 章：约束检索（SAR/nDCG/转换链）；
- 第 5 章：生成（FCR/EGC/SIF/PIV + 等 token/等规模/同 reranker 对照）；
- 第 6 章：自维护（学习曲线/回归率）。

## 8. 一句话

**A 给解释，B 给约束，C 给论文。**
你现在最该做的不是换建图方式，而是把 A 的 61 条降级成注解、把 B 的证据补齐——**路线不变，质量补齐**。
