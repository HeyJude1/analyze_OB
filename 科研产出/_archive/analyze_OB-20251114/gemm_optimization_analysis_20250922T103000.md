# OpenBLAS GEMM 优化策略报告

## 1. 算法设计层次分析

### 1.1 以空间换时间的优化设计
- **微内核（Microkernel）复用**：所有架构均采用 4x4、4x8 等固定尺寸微内核，将 A 矩阵元素在寄存器中复用多次（如 4x8 内核中每个 A 元素被使用 8 次），显著减少内存访问次数。
- **多尺寸内核组合**：为不同 N 值（12、8、4、2、1）设计独立内核，避免运行时分支开销，最大化计算密度。
- **块划分（Blocking）**：通过 K 循环展开（如 x86_64 中展开 4 次），将大矩阵分解为小块，提升缓存局部性。

### 1.2 以时间换空间的优化设计
- **寄存器密集型计算**：在 ARM64 和 x86_64 中，使用 16~32 个 SIMD 寄存器（如 v8-v31、yvec0-yvec15）暂存中间结果，牺牲寄存器资源换取内存带宽节省。
- **预取指令（Prefetch）**：在 ARM 和 x86 架构中主动插入 `prfm` / `prefetcht0` 指令，提前加载 B 矩阵和 C 矩阵数据，以时间延迟换取后续访存零等待。

## 2. 代码优化层次分析

### 2.1 性能加速的代码优化
- **循环展开（Loop Unrolling）**：
  - ARM64 Cortex-A53：K 循环展开 2 次，匹配流水线深度。
  - ARM VFPv3：K 循环展开 8 次，最大化 FMA 吞吐。
  - x86_64 Sandy Bridge：K 循环展开 4 次，提升指令级并行度（ILP）。
- **条件分支优化**：`gemm_beta.c` 根据 `beta` 值分支，避免无意义乘法，减少无效计算。
- **指针算术优化**：使用多个指针（如 `b1_`, `b2_`）替代复杂索引，减少地址计算开销。

### 2.2 代码顺序调整优化
- **指令重排**：在汇编代码中，将内存加载（`vld1q_f64`、`vldmia`）与计算指令（`fmla`、`fmuls`）交错，隐藏内存延迟。
- **数据预取与计算重叠**：在 ARM 和 x86 中，预取指令紧随计算指令放置，确保数据在需要前到达缓存。
- **存储延迟隐藏**：在 x86_64 中，先计算所有 FMA 结果，再统一写回 C 矩阵，避免写入阻塞计算流水线。

## 3. 特有指令层次分析

### 3.1 专有指令使用
| 架构 | 专有指令 | 用途 |
|------|----------|------|
| ARM64 (Cortex-A53) | `fmla v8.2d, v0.2d, v4.d[0]` | NEON FMA 指令，单指令完成乘加，提升吞吐 |
| ARM VFPv3 | `fmacs s8, s0, s16` | VFP 单精度 FMA，减少指令数 |
| x86_64 (Sandy Bridge) | `vfmadd213pd yvec15, yvec6, yvec7` | AVX2 FMA3 指令，256-bit 双精度并行计算 |
| x86_64 | `prefetcht0` / `prefetcht2` | 预取 A/B 矩阵到 L1/L2 缓存 |
| ARM64 | `prfm pstl1keep` | 预取 C 矩阵到 L1 缓存，保持热数据 |

### 3.2 围绕专有指令的优化设计
- **向量化数据布局**：
  - ARM64：B 矩阵按行主序加载，匹配 NEON 128-bit 宽度，实现 4x12 数据块并行处理。
  - x86_64：A 矩阵列主序、B 矩阵行主序，适配 AVX2 256-bit 向量，实现 4x8 计算块。
- **寄存器分配策略**：
  - 所有架构均将 16~32 个 SIMD 寄存器分配给中间结果，避免寄存器溢出（spill）。
  - 使用 `movi` 指令一次性清零寄存器（如 `movi v8.16b,#0`），减少指令数。
- **内存对齐与访问模式**：
  - x86_64 使用 `movapd`（对齐加载）和 `movlpd/movhpd`（非对齐加载）组合，最大化吞吐。
  - ARM 使用 `vldmia`（多寄存器加载）一次性加载 4 个单精度寄存器，减少指令周期。

## 总结：通用优化策略

1. **微内核 + 多尺寸组合**：固定尺寸微内核是 GEMM 优化的基石，应作为所有 BLAS 算子的标准设计模式。
2. **FMA 指令优先**：优先使用硬件支持的融合乘加指令，避免拆分为乘+加指令。
3. **预取与缓存友好布局**：必须显式插入预取指令，并根据数据访问模式设计矩阵布局（行/列主序）。
4. **循环展开与指令重排**：根据目标微架构流水线深度展开循环，交错加载与计算指令以隐藏延迟。
5. **寄存器密集型设计**：牺牲寄存器资源换取内存带宽降低，是高性能计算的核心权衡策略。

> 本报告基于 OpenBLAS 中 ARM64、ARM VFPv3、x86_64 与通用实现的对比分析，提炼出可复用于其他线性代数算子（如 TRMM、SYRK）的通用优化范式。
