## 2. 为什么必须补 x86 / ARM（而不是可选）

1. **论文的核心增量是"跨架构策略可迁移性"**：需要同一策略在 x86 / ARM / RVV 三个架构上的实现证据，才能回答"哪些策略架构无关、哪些参数自适应、哪些架构特定"。只有 RVV 时，这个问题无法回答。
2. **KG 的"全面"不是靠算子多，而是靠"架构 × 算子"覆盖**：12 算子 × 2 架构（generic+RVV）只能覆盖一条轴；补 x86/ARM 后同一批算子能有 3–4 个架构的实现，图谱的边才真正"跨架构"。
3. **答辩会被问**："你的图谱只有 RISC-V 吗？"——必须能回答"x86/ARM 也入库了，只是性能实验在 x86 + RISC-V 上做"。

### 3.2 Schema 变化（小改，不重做）

- `SourceArtifact` / implementation 增加 `arch`（x86_avx2 / x86_avx512 / arm_neon / arm_sve / rvv / generic）、`isa`、`uarch`；
- `OptimizationStrategy` 增加 `arch_scope`（`arch_agnostic` / `parameterized` / `arch_specific`）与 `arch_evidence[]`（每个 arch 的实现/参数/证据）；
- 新增关系 `STRATEGY_IMPLEMENTED_ON`（策略 → implementation/arch），原有 14 类关系不变。

### 3.3 抽取流程（复用 S0–S6）

- **S0**：按 `arch_sources` 扫描/复制文件，登记 sha256/行号；
- **S1**：C 抽 intrinsics/prefetch/unroll/pack；汇编抽指令 mnemonics（`vfmadd`/`vmla`/`fmla`/`prefetcht0`/`prfm`/`vle64` 等）、unroll 块、prefetch、寄存器分块线索；
- **S2**：同架构 generic vs optimized 差分（C 对可用时）；汇编-only 用"特征存在"，标 `method=static`；
- **S3/S4**：策略统一命名 + 跨架构对齐；同族策略合并时保留各 arch 参数（如 x86 unroll=4 vs RVV unroll=8）；
- **S6**：校验 + 统计。
